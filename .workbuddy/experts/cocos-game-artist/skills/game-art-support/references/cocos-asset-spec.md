# Cocos 侧资源规格

> 目标：美术交付的资产**能直接进 Cocos 工程并跑起来**。所有规格判断以对应 Cocos Creator 版本与目标平台文档为准；不确定的标「需实测验证」。

## 一、设计分辨率与适配

- **先问清设计分辨率**（如 720×1280 竖屏 / 1280×720 横屏），所有 UI 资产按它推导；
- 适配策略会影响资产规格：等比缩放会留黑边或用背景延展，**UI 底图与背景图必须做成可延展或留出血**；
- **UI 关键元素不要贴设计边**：屏幕比例差异会裁掉边缘，重要内容留安全区；
- 九宫格（Sliced）用于可拉伸面板与按钮底，**生成时就按"中间可拉伸、四角不可拉伸"的构图来画**，并告知九宫格边距建议值。

## 二、资产规格对照表

| 资产类型 | 建议规格要点 |
|---|---|
| 角色 / 怪物 | 同族统一画布比例（如 1:1 或 3:4）；留 8–10% 安全边距；出 2 倍尺寸再缩 |
| 场景瓦片 | 严格正整数瓦片尺寸，**贴图必须无缝**（左右/上下可拼接）；不要带方向性阴影，阴影交给引擎 |
| 背景 | 按设计分辨率出图，预留出血；分近景/中景/远景时按层分别导出 |
| UI 按钮 | 三态（常态 / 按下 / 禁用）+ 九宫格边距；状态差异靠明度与描边，不靠整体换色 |
| 图标 | 统一画布尺寸与内边距（视觉重量一致）；不要每个图标各自贴边 |
| 特效贴图 | 纯色底或黑底（加法叠加用黑底）；不要自带背景 |
| 字体 | 只有确实需要时才用图片字；常规文字用系统字体 + 描边样式 |

## 三、命名与图集分组

- 命名规范见 `asset-inventory.md`；
- **图集分组原则**：**同屏同时出现的资产归同一图集**（角色与它的特效、同一关的怪物与瓦片）；
- 不要把所有 UI 塞进一个图集：首页 UI 与战斗 UI 分开，避免首屏加载无关资源；
- 首屏必需资源与后续资源分离，后续资源走分包或远程加载（**具体策略按版本与平台文档确认**）。

## 四、纹理与内存约束

| 约束 | 要求 |
|---|---|
| 尺寸 | 优先 2 的幂（2/4/8…1024）；非 2 幂在部分平台会无法压缩或浪费显存 |
| 透明边 | 导出前**必须裁掉**（用 `art_asset_tools.py trim`），否则浪费显存与图集空间 |
| 格式 | 透明小图 PNG；不透明大图可考虑 JPG/WebP（取决于平台支持与是否需压缩） |
| 同屏数量 | 同屏精灵数量是常见性能瓶颈，规格评审时要提醒；具体上限**需实测验证** |
| 单图尺寸 | 超过 1024 的大背景考虑切分或降分辨率，不要靠单张巨图 |

## 五、导入前自检（交付给工程之前的最后一道）

- [ ] 尺寸与规格表一致，且为 2 的幂（或已说明为何不是）
- [ ] 透明边已裁掉，四周无半透明脏点
- [ ] 无外发光、无边缘杂色（会污染图集）
- [ ] 命名符合规范，版本号正确
- [ ] 同族资产画布比例一致
- [ ] 朝向统一（或已说明需要独立左右版本）
- [ ] 无文字、无签名、无品牌元素
- [ ] 已标注哪些是 AI 生成、哪些需人工精修

## 六、常见"进引擎后才发现"的问题

| 现象 | 根因 | 预防 |
|---|---|---|
| 边缘一圈白边 | 抠图容差太小 / 生成时用了渐变底 | 生成即用纯色底 + 抠图后检查边缘 |
| 图集出现红绿杂色块 | 图集间留白不足，相邻图纹理溢出 | 导出时四周留 1–2px 透明缓冲 |
| 缩放后模糊 | 用了小于显示尺寸的图 | 按目标显示尺寸出图，或出 2 倍再缩 |
| 瓦片拼接有缝 | 瓦片不是无缝贴图 | 生成时明确要求可无缝拼接，并在引擎里验证 |
| 面板拉伸后变形 | 未使用九宫格，或九宫格边距设错 | 画图时预留不可拉伸的四角 |
| 同屏卡顿 | 单图过大、图集分组不合理、精灵数量过多 | 规格评审阶段就按性能预算约束 |
