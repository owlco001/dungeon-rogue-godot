# 交付物规范（Markdown 优先）

> 默认交付物是 **Markdown 美术文档**，不是对话里的一段回复，也不是 PPT。PPT 属"确认后再做的动作"。

## 一、三类文档与命名

| 文档 | 命名 | 什么时候出 |
|---|---|---|
| 美术风格提案 | `<项目名>-美术风格提案.md` | 入口 A 风格定调 |
| 美术评审报告 | `<项目名>-美术评审报告.md` | 入口 C 评审 |
| 美术资产清单 | `<项目名>-美术资产清单.md` | 入口 B 盘点、入口 D 产出前后 |

- 项目名用中文项目名或代号，去掉空格与特殊字符；
- 需要阶段性留版时加批次或日期后缀：`…-美术资产清单-第2批.md`；
- 文件名冲突时加序号（`…-美术资产清单-2.md`），**不要覆盖已有文件**；
- 默认存到当前工作区根目录，用户指定目录则用指定的。

## 二、风格提案必含章节

```markdown
# 《项目名》美术风格提案

> 版本 v1 ｜ 日期 YYYY-MM-DD ｜ 设计分辨率 720×1280 ｜ 目标平台 XX小游戏

## 1. 风格锚点（逐字复用，生成时整段复制）
## 2. 色彩板（色号 + 明度 + 用途）
## 3. 明度阶梯与背景/主体分离要求
## 4. 各资产类别的表现约定（角色 / 怪物 / 场景 / UI / 图标 / 特效）
## 5. 禁忌清单
## 6. 参考坐标（提取的是哪些结构特征）
## 7. 第 1 批基准图产出计划（只出 1–2 张）
```

## 三、对话里回什么

**不要把 .md 全文再贴一遍。** 交付时只给三块：

1. 文件已生成 + 路径
2. **简短摘要**：关键结论 3–5 条（含已确认 / 待定）
3. **询问一次**：是否需要 PPT

```text
已生成：月夜瓜田-美术风格提案.md

风格锚点：国风剪影 + 月夜高对比双色调 + Q 版三头身，左上主光、统一 3px 描边。
关键结论：
① 色彩板 6 色已定，主体明度比背景高 2 档以上，缩略图可辨识；
② 角色只做朝右单方向，左向走代码镜像；独眼类怪物需左右各一版；
③ 生成一律纯色底（#FF00FF），再 keyout 转透明底，双版本交付；
④ 待定：瓦片是否需无缝拼接（影响场景批次的出图方式）。

需要我把这份提案做成 PPT 吗？（要 / 不要）
```

## 四、PPT 只在确认后生成

- 用户回答「要 / 可以 / 做成 PPT」→ 按 `ppt-module.md` 生成，**内容只复用已确认文档**
- 用户未回答或说不需要 → **到此为止，不再追问第二次**
- 用户主动提出「做成 PPT / 汇报 / 提案演示」→ 可直接生成

命名同 .md，扩展名换 `.pptx`，放同一目录。**PPT 默认文件名由 `meta.doc_type` 决定，与三类文档对齐**：

| `meta.doc_type` | 默认输出名 |
|---|---|
| `风格提案`（缺省） | `<项目名>-美术风格提案.pptx` |
| `评审报告` | `<项目名>-美术评审报告.pptx` |
| `资产清单` | `<项目名>-美术资产清单.pptx` |

> 其他取值会被数据校验拦下并提示可用值。

## 五、自检

- [ ] .md 已落盘（不是只在对话里输出）
- [ ] 文件名符合命名规范，且未覆盖已有文件
- [ ] 顶部有版本 / 日期 / 设计分辨率 / 目标平台元信息行
- [ ] 风格提案含"禁忌"与"待定"两部分
- [ ] 对话里只给摘要 + 路径，未重复贴全文
- [ ] 询问了是否要 PPT，且只问一次
