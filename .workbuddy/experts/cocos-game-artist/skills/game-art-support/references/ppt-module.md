# PPT 输出模块（确认后启用）

> 把**已确认**的美术内容转成带原生图表的 PPT。只做"文档 → PPT"，不新增设计、不改风格锚点。

## 一、触发条件

**默认不出 PPT。只有在用户明确确认后才启用**（见 `deliverables.md`）：

- ✅ 交付 Markdown 美术文档后，用户回答「要 / 可以 / 做成 PPT」
- ✅ 用户主动提出「做成 PPT / 汇报 / 风格提案演示 / 给美术外包看」
- ❌ 只在 Markdown 阶段就出 PPT —— 顺序不能颠倒
- ❌ 用户未回答或说不需要 —— 停在 Markdown，**不再追问第二次**

## 二、页结构（10 页，缺数据整页跳过）

| 页 | 内容 | 形式 |
|---|---|---|
| 1 | 封面：项目名 + 一句话风格定位 + 设计分辨率 + 目标平台 | — |
| 2 | 风格锚点（画风 / 视角 / 光照 / 线宽 / 质感 / 比例 / 色彩倾向 / **禁忌**） | 表格 |
| 3 | 色彩板（色名 / 色号 / 用途 / 明度档） | 带**色块底色**的表格 |
| 4 | 明度阶梯（高光→阴影 6 档与用途） | 表格 |
| 5 | 资产清单（类别 / 数量 / 优先级 / 规格要点 / 图集分组） | 表格 |
| 6 | **资产数量分布**（按类别） | **饼图**（占比） |
| 7 | **产出批次计划**（每批数量与目的） | **条形图** + 表格 |
| 8 | 缺口清单（缺什么 / 优先级 / 阻塞什么 / 状态） | 表格 |
| 9 | 评审结论与需精修项 | 表格 |
| 10 | 下一步与待定事项 | 列表 |

## 三、图表选型规则

| 数据特征 | 图表 | 理由 |
|---|---|---|
| 资产类别数量构成 | **饼图** | 看产能分布在哪些类别 |
| 各批次产出量与节奏 | **条形图** | 比较批次规模 |
| 优先级分布（P0/P1/P2） | 表格（不进图） | 只有三档，图不如表清楚 |

**禁用**：3D 图表、双 Y 轴、用饼图表示趋势、用图表表达"风格"这类无法量化的内容。

## 四、视觉与文案规范

- **主色使用风格锚点里的主色**，PPT 本身就是风格示范（若与技术限制冲突，说明后改用中性主色）；
- **色彩板页必须带真实色块**：单元格底色填该色号的 RGB，让人一眼看到配色；
- 每张图下方固定一行「一句话：……」；
- 页脚固定：`版本 ｜ 日期 ｜ 设计分辨率 / 平台 ｜ 待定项数量`；
- 数值保留原样（尺寸写 `256×256`，色号写 `#RRGGBB`），不做改写。

## 五、数据契约（JSON）

字段全部可选，**没有的键就省略**（对应页自动跳过）：

```json
{
  "meta": { "project": "月夜瓜田", "tagline": "国风剪影 + 月夜高对比双色调",
            "resolution": "720×1280 竖屏", "platform": "抖音小游戏",
            "version": "v1", "date": "YYYY-MM-DD",
            "accent": "#C97B3A",
            "doc_type": "风格提案" },
  "anchors": [{ "item": "画风", "value": "国风水墨剪影" }],
  "palette": [{ "name": "主色", "hex": "#8B5A2B", "usage": "主角", "luminance": "高" }],
  "luminance": [{ "level": "高光", "range": "80–95", "usage": "金属 / 水面" }],
  "assets": [{ "category": "角色", "count": 6, "priority": "P0",
               "spec": "256×256 PNG 透明", "group": "char_atlas" }],
  "batches": [{ "batch": "第1批", "content": "1 角色 + 1 怪物基准", "count": 2,
                "goal": "敲定风格锚点与线宽" }],
  "gaps": [{ "asset": "char_hero_idle", "category": "角色", "priority": "P0",
             "blocks": "核心循环验收", "status": "未开始" }],
  "review": { "verdict": "小改", "summary": "3 张通过、5 张小改、1 张重做",
              "issues": [{ "asset": "slime_normal", "issue": "主体与背景明度差不足",
                           "fix": "背景压暗 1 档，主体加 1px 深色描边", "priority": "P0" }] },
  "next": ["先出第 1 批基准图", "待定：瓦片是否无缝拼接"]
}
```

**可选的一句话说明键**（不写就用兜底文案，写了就替换对应页图表下方的说明）：

| 键 | 替换哪一页的说明 |
|---|---|
| `anchors_note` | 风格锚点页 |
| `palette_note` | 色彩板页 |
| `luminance_note` | 明度阶梯页 |
| `assets_note` / `assets_chart_note` | 资产清单页 / 资产数量分布页 |
| `batches_note` | 产出批次计划页 |
| `gaps_note` | 缺口清单页 |

**meta 里的两个特殊键**：

| 键 | 作用 | 不写时 |
|---|---|---|
| `accent` | 用风格锚点的主色作为 PPT 主色（`#RRGGBB`） | 用脚本内置青碧主色 |
| `doc_type` | 决定默认输出文件名：`风格提案` / `评审报告` / `资产清单` | 按 `风格提案` |

完整示例见 `templates/art-data.example.json`（示例内容，非真实项目）。

**脚本会拒绝出图的情况（数据校验）**：

| 情况 | 行为 |
|---|---|
| **整个板块没有数据** | 删掉对应的键即可，那一页**自动跳过**（允许） |
| **字段值不合法** | 脚本**列出全部问题并停止**，不出图 |

会被判为不合法的：图表数值位放了 `null` 或无法转换的字符串、类别与数值个数不一致、`palette` / `assets` 等写成对象但期望数组、数组元素不是对象。

**长清单自动截断**：表格行数超过当前页可用高度时，脚本会截断并补一行「共 N 条，此处仅显示前 M 条」——
不截断会把表格撑到画布外（实测 30 条问题时表高 10.54 英寸，而画布只有 7.5 英寸），产物却仍"生成成功"。完整清单以 Markdown 文档为准。

## 六、硬约束

- **不新增设计**：PPT 里每条内容都必须来自已确认文档；缺的板块整页跳过，并写进第 10 页待定项。
- **禁忌清单必须上页**：第 2 页的风格锚点里“禁忌”不可省略。
- **色彩板必须是真实色号**，不得用文字描述代替。
- **生成图不作为 PPT 插图滥用**：本模块只出提案与清单类 PPT，不把生成的美术图堆进版面（如需插图由用户自行提供）。
- **原生图表，不贴图**：交付后可在 PowerPoint / WPS 里改数据改样式。

## 七、交付前自检

- [ ] 脚本回显页数与图表数符合预期（图表 ≥ 1）
- [ ] 色彩板单元格底色为真实色号
- [ ] 第 2 页含禁忌清单
- [ ] 第 10 页列出待定项
- [ ] `.pptx` 能被重新打开（无"需要修复"提示）
