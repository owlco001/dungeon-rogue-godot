## 一、v0.7 差距分析（终稿版）

> 严重度：**P0** = 系统级断裂，必须 v0.8 修；**P1** = 明显缺陷，建议修；**P2** = 打磨项。

### 1.1 P0-1 三选一把被动压到只剩 1/3 槽位，超武合成 ≤10% 的局可达

**算法原文**（`scripts/player.gd:1052–1065`）：

```gdscript
var pools := [synth, wnews, wups, snew, sups, pnews, pups]
for p in pools: p.shuffle()
var opts: Array = []
var i := 0
while opts.size() < 3:
    var added := false
    for p in pools:
        if i < p.size() and opts.size() < 3:
            opts.append(p[i]); added = true
    if not added: break
    i += 1
```

语义：**按 `pools` 固定顺序，取前 3 个非空池的第 i 项**。`pnews`（新被动）排第 6、`pups`（被动升级）排第 7。

**合并后的准确根因链（必答题的正式回答）**

四条条件**共同**锁死，缺一不成立；修复必须全部覆盖：

| 编号 | 锁 | 位置 | 机制 |
| --- | --- | --- | --- |
| **RC-1** | **选池顺序锁（主锁）** | `player.gd:1052` | `pnews/pups` 排在 7 个池的末两位，「前 3 个非空池」选择器意味着**被动永远只能竞争第 3 个槽位**，前两槽被 `wnews/wups`（及前期的 `snew/sups`）占死 |
| **RC-2** | **pnews 先于 pups 的偏置锁** | `player.gd:1052`（同一行顺序） | 即便被动进槽，也是"新被动"优先于"被动升级"。超武需要的是**某一个特定被动升到 Lv5**，而算法要求先把 6 个不相关的新被动吃满（`pnews` 清空后 `pups` 才有机会进槽）→ 把一个被动练到 Lv5 的期望代价 ≥ 10 次"第 3 槽命中" |
| **RC-3** | **合成自锁** | `player.gd:999` | `if int(passives.get(need_p,0)) < PASSIVE_MAX_LV: continue` → `synth` 池要求"对应被动 Lv5"，而被动受 RC-1/RC-2 压制 → `synth` 自锁为空。**循环依赖**：要合成 → 先被动 Lv5 → 而被动几乎不可达 |
| **RC-4** | **升级预算放大器** | `player.gd:1005–1013` + `WEAPON_MAX_LV=8` | 每把武器到 Lv8 需 7 次升级，6 把 = 48 次 > 一局 32 次 → `wups` 在整局恒非空，持续占据前两槽 |

**排除项（对柯桥良指认的复核结论）**

- 柯桥良指认 `player.gd:1022` 的 `passives.has()` 锁死 `pnews`。**复核结论：不成立。**
  - `player.gd:1022` 实际是 `new_weapon` 词条的 `desc` 字符串拼接行（`"desc": "%s,自动攻击" % String(SCHOOL_NAMES.get(...))`），**不含任何 `passives.has`**。
  - 真正含 `passives.has` 的是 `player.gd:1031`，它位于 `if passives.size() < PASSIVE_SLOTS`（`:1029`）之内，语义是"**不重复提供已持有的被动**"——是正确的去重过滤，不是锁。
  - **决定性证据**：逐行镜像算法跑 32 次升级（`_trace.py`），`pnews` 规模**从第 1 次升级起恒等于 12，从未为空**；且随机玩家从第 9 次升级起就能在选项里看到 `new_passive`。若 `has()` 真的锁死了 `pnews`，它一次都不会出现。
- 但柯桥良的**修复方向仍然有价值**：把被动改成"可叠加词条 + StatBlock 修饰符"（02-architecture §4.7-2）能支持更高的 `passive_up` 权重与数据配置化，只是它**不是解锁被动的必要条件**。据此把 A3 拆为 A3a/A3b（§0.2 M-3）。

**定量结论（三种玩家画像，终稿口径）**

| 玩家画像 | 被动类槽位占比 | 每局合成超武 | 来源 |
| --- | --- | --- | --- |
| 定向玩家（冲着某把武器 Lv8 + 对应被动 Lv5 去） | **2.1%**（v0.7）→ **41–59%**（v0.8） | **0 把（0%）** → **100% 的局 ≥1 把** | `_sim2.py`（v0.7）、`_sim5.py`/`_slotrule2.py`（v0.8） |
| 休闲玩家（50% 跟推荐 / 50% 随机） | — | v0.8：**47% 的局 ≥1 把** | `_slotrule2.py`，500 局 |
| 纯随机玩家 | v0.7：被动占 1/3 槽（34%），**2.4% 的局 ≥1 把** | v0.8：2.4% | `_slotrule2.py`，500 局 |

> **头条表述（终稿统一口径）**：v0.7 下，**只有跟着"练满一把武器去合成"的明确目标走的玩家能合成超武，且实测 0% 成功；纯随机玩家 2.4%，休闲玩家需 v0.8 才有 47%**。v0.8 目标是把定向玩家拉到 100%、休闲玩家（跟随推荐 UI）作为主要达成面。
> **A-1 判据的实现依赖**：≥9/10 局的达标前提是「推荐金框」UI 落地（§3.4）。算法只负责把正确选项放进三选一，把它选出去靠推荐高亮。

**连带影响**：`GameData.PASSIVES` 12 项×5 级实际不可达 → `player.gd` 的 `_dmg_mult/_cd_mult/_crit_chance/_area_mult/_xp_mult/_duration_mult` 六个派生函数恒返回基线值；`SUPERWEAPONS` 19 条路线的合成演出（`player.gd` 金色大闪/震屏/顿帧）从未被玩家见过；成就 `super1/5/19`、`arsenal` 不可达 → 8 天赋点永久丢失；玩家**局内没有任何生存成长手段**（hp/armor 被动拿不到）。

**修复方案（覆盖 RC-1~RC-4 全部）**：见 §3.1。

## 二、三主题分层结构

### 2.1 分层总览

三个主题不做并列，而是拆成**一条依赖链上的五层**。每层可独立发布、独立验收；砍单线从 L4 往上砍。

```
L0 地基层（架构，柯桥良 A1–A9）        —— 不做完全部上层都白做
   └─ L1 构筑能成型（主题1）            —— 最小可发布版 v0.8.0
       └─ L2 内容接线（主题2 的"内容"半边 + 12 遗物 + 宝箱）
           └─ L3 活下去（主题3：波次/计时/评分 + Boss 全差异化）
               └─ L4 地牢有形状（主题2 的"空间"半边：程序化房间 + 寻路）
```

| 层 | 内容 | 依赖 | 人日 | 风险 |
| --- | --- | --- | --- | --- |
| **L0** | hitstop 重构、数据配置化第一批、StatBlock、EntityRegistry+空间网格、Arena 烘焙、自动化验证集、首包瘦身、存档版本化、FX 池化（= 02-architecture §5 A1–A9，其中 A3 拆 A3a/A3b） | 无 | **16.5** | 中–高 |
| **L1** | 三选一改加权池+漏斗+保底、刷怪曲线去锯齿、局外经济重配、新手 3 分钟、无尽直连入口、被动选择器修正（A3a） | L0 的 A2（数据表） | **5.1** | 中 |

## 三、L1 构筑能成型（设计案）

### 3.1 三选一：从「前 3 非空池」改为「加权无放回抽取 + 漏斗 + 保底」

**覆盖 RC-1~RC-4 的完整规则**：

```gdscript
# player.gd::build_levelup_options（v0.8 重写）
# RC-3 处理：合成超武条件满足时，仍强制置顶占 1 槽（保留 v0.7 行为）
# RC-1 处理：其余槽位改为加权无放回抽取，不再按池顺序轮转
const OPT_WEIGHT := {
    "weapon_up":   30,   # 若该武器 == 当前"漏斗武器"，权重 ×2.0
    "new_weapon":  22,   # 持有武器 >= 4 把后降到 8
    "passive_up":  22,   # 若该被动 == 漏斗武器的合成所需被动，权重 ×3.0   ← RC-2 处理
    "new_passive": 18,   # 持有被动 >= 4 个后降到 6
    "skill":        8,   # new_skill / skill_up 合计（保持 v0.7"通用槽只有一个"规则）
}
# RC-4 处理：保底（bad-luck protection）
#   连续 2 次升级未出现 passive_up → 第 3 次强制塞入 1 个 passive_up
#   （优先玩家已持有的等级最高者；若已满级则给一个未持有的新被动）
# RC-3 处理：合成引导（funnel）
#   某武器达到 Lv8 的那一刻，下一次升级强制提供其合成所需被动的
#   new_passive 或 passive_up（占 1 槽）→ 打破"要合成先被动 Lv5"的循环
# 附带：pnews/pups 的去重过滤（player.gd:1031）与 PASSIVE_SLOTS 上限（:1029）保留不动
#
# ── 武器槽规则定案（W1–W4，回应"槽满后被动成为新瓶颈"的边界问题）──
# W1 槽满即自然移出：weapons.size() >= 6 时 new_weapon 无候选（:1014 的上限判断保留），
#    不需要额外的"移出规则"——候选池为空即不参与抽取
# W2 槽满补权：槽满后 passive_up 权重 22 → 30（语义：武器扩容线封顶后，
#    被动是唯一成长轴，应占主导）。实测影响极小（见下表），此条是语义保险而非必需
# W3 不做"槽满后可替换武器"：换枪 = 丢失已投入的升级，会让 48 次升级预算的问题更糟；
#    武器替换属于 v0.9 若引入"武器熔铸"再议
# W4 funnel ×2/×3 与保底不受槽满影响（合成引导是 RC-3 的解法，必须全程有效）
```

**权重推导**：34 次升级 × 3 槽 = 102 槽位。中期（4 武器 + 4 被动后）权重和 = 30+8+22+6+8 = 74 → `passive_up` 占 29.7%、`new_passive` 占 8.1% → 被动类 ≈ **38%**。前期 `new_weapon` 权重高（22）保证武器多样性。

**武器槽瓶颈的实测结论（定案依据，`_slotrule.py` / `_slotrule2.py`）**：
